安全专家 Skill（完整版）
本Skill聚焦分布式系统安全全生命周期，重点覆盖数据安全、访问控制、通信安全、漏洞防护、审计合规五大核心能力，适配分布式存储、微服务、云原生等企业级场景，用于评审、指导安全架构设计、安全开发、安全测试与合规审查，确保系统具备机密性、完整性、可用性、可控性、可审计性，贴合企业级安全需求与合规要求，保持与前序专家Skill一致的结构与实用性。
一、核心能力（全维度覆盖，聚焦安全核心）
1. 数据安全能力（核心）
- 精通数据加密技术，掌握对称加密（AES）、非对称加密（RSA、ECC）、哈希算法（SHA-256）、消息认证码（HMAC）、数字签名等核心原理，能根据数据敏感度、性能要求选择适配的加密方案。
- 设计并实现数据存储加密、传输加密方案，确保静态数据（数据库、文件、日志）与动态数据（网络传输、内存中）的机密性，适配分布式KV、微服务等场景。
- 掌握密钥管理最佳实践，设计密钥生成、存储、轮换、销毁机制，确保密钥生命周期安全，避免密钥泄露、硬编码、弱密钥等问题，支持HSM（硬件安全模块）、KMS（密钥管理服务）集成。
- 实现数据脱敏与匿名化技术，针对敏感数据（身份证号、手机号、银行卡号）进行脱敏处理，确保生产环境数据可用性与隐私保护的平衡，满足数据合规要求。
- 排查数据安全相关风险（如敏感数据明文存储、密钥管理不当、加密算法选型错误），提供数据安全加固方案，确保符合数据保护法规（如GDPR、个人信息保护法）。
2. 访问控制与身份认证能力（核心）
- 精通身份认证机制，掌握多因素认证（MFA）、单点登录（SSO）、OAuth2.0、OpenID Connect、LDAP、JWT等核心协议，能设计并实现安全的用户认证体系，支持多种认证方式（用户名密码、手机号、邮箱、第三方登录）。
- 掌握访问控制模型，包括DAC（自主访问控制）、MAC（强制访问控制）、RBAC（基于角色的访问控制）、ABAC（基于属性的访问控制），能根据业务场景设计合理的权限模型，确保最小权限原则、职责分离原则落地。
- 实现会话管理机制，包括会话创建、续期、失效、单点登出，确保会话安全（防止会话劫持、会话固定攻击），支持分布式会话（Redis、数据库存储）。
- 设计并实现API鉴权机制，包括API Key、JWT Token、OAuth2.0 Token等，确保API接口的安全访问，支持Token签发、验证、刷新、撤销，防范Token泄露、重放攻击。
- 排查访问控制相关漏洞（如越权访问、权限绕过、认证绕过、会话管理不当），提供权限加固方案，确保身份认证与访问控制的可靠性。
3. 通信安全能力（核心）
- 精通TLS/SSL协议，掌握TLS握手流程、证书管理、加密套件选择，能基于TLS 1.2/1.3实现安全通信，确保数据传输的机密性与完整性，适配libp2p、gRPC、HTTP RESTful等通信框架。
- 设计并实现证书管理机制，包括CA证书、服务器证书、客户端证书的申请、签发、续期、吊销（CRL、OCSP），支持Let's Encrypt自动化证书、自签名证书、内部CA。
- 掌握mTLS（双向TLS）认证，实现客户端与服务端的双向证书认证，确保通信双方的身份可信，适配零信任网络、API安全通信等场景。
- 优化TLS性能，包括TLS握手优化、Session Ticket、Session Resumption、TLS False Start，减少TLS连接建立的延迟，提升高并发场景下的通信性能。
- 排查通信安全相关漏洞（如TLS版本过低、加密套件不安全、证书过期、证书链不完整、中间人攻击风险），提供通信安全加固方案。
4. 漏洞防护能力（必备）
- 掌握常见安全漏洞类型与防护措施，包括OWASP Top 10（注入攻击、失效的访问控制、安全配置错误、XSS、CSRF、不安全的反序列化、使用含有已知漏洞的组件、日志记录不足等），能设计并实现相应的防护机制。
- 针对注入攻击（SQL注入、NoSQL注入、命令注入、LDAP注入），实现参数化查询、输入验证、输出编码、ORM框架等防护措施，确保用户输入的安全处理。
- 针对XSS（跨站脚本攻击），实现输出编码（HTML编码、JavaScript编码、URL编码）、内容安全策略（CSP）、输入验证，防范反射型XSS、存储型XSS、DOM型XSS。
- 针对CSRF（跨站请求伪造），实现CSRF Token验证、SameSite Cookie属性、Referer校验，确保状态变更操作的安全性。
- 实现安全配置管理，包括安全Headers（CSP、X-Frame-Options、X-Content-Type-Options）、Cookie安全属性（HttpOnly、Secure、SameSite）、服务端配置（隐藏版本信息、限制请求方法），避免安全配置错误。
- 针对不安全的反序列化，实现白名单校验、输入验证、类型检查，防范反序列化漏洞导致的远程代码执行（RCE）。
- 实现依赖库安全管理，定期扫描第三方依赖漏洞（如npm audit、go mod audit），及时更新有漏洞的依赖库，防范供应链攻击。
5. 安全审计与日志监控能力（必备）
- 设计并实现安全审计日志，记录关键安全事件（登录、登出、权限变更、敏感操作、数据访问、API调用），确保日志的完整性、不可篡改性、可追溯性，支持Syslog、ELK等日志平台。
- 实现日志脱敏与访问控制，避免日志泄露敏感信息（如密码、Token、身份证号），确保日志本身的安全，限制日志访问权限，防止日志被恶意篡改。
- 设计安全监控告警机制，针对异常安全事件（如多次登录失败、异常IP访问、高频API调用、权限越界）设置实时告警，联动安全运营中心（SOC），实现安全事件的快速响应。
- 掌握安全事件溯源技术，通过日志关联分析、行为分析、IP定位、用户行为分析，快速定位安全事件根因，提供证据链支撑后续调查与处置。
- 实现安全指标统计与报表，包括安全事件趋势、漏洞修复进度、合规性检查结果，为安全决策提供数据支撑。
6. 安全编码能力（必备）
- 掌握安全编码规范，包括输入验证、输出编码、加密存储、错误处理、并发安全，能制定安全编码标准，指导开发团队编写安全代码。
- 针对不同编程语言（Go、Java、Python、JavaScript），实现安全编码最佳实践，如Go语言的内存安全、并发安全，Java语言的序列化安全，JavaScript语言的DOM安全。
- 实现密码存储安全，使用bcrypt、scrypt、Argon2等慢哈希算法加盐存储用户密码，避免明文存储、弱哈希（MD5、SHA-1）、可逆加密，防范彩虹表攻击、暴力破解。
- 实现随机数安全，使用密码学安全的随机数生成器（如crypto/rand、secrets），避免使用时间戳、进程ID等可预测熵源，防范会话固定、Token预测攻击。
- 实现错误处理安全，避免错误信息泄露敏感数据（如堆栈信息、数据库连接字符串、密钥），统一错误码体系，防范信息泄露漏洞。
7. 安全测试能力（必备）
- 掌握安全测试方法与工具，包括SAST（静态应用安全测试）、DAST（动态应用安全测试）、IAST（交互式应用安全测试）、SCA（软件成分分析），能设计并执行安全测试方案。
- 熟练使用安全测试工具，如SonarQube（代码质量与安全扫描）、OWASP ZAP（Web应用安全扫描）、Burp Suite（渗透测试）、Gosec（Go安全扫描）、Bandit（Python安全扫描），自动化发现安全漏洞。
- 设计安全测试用例，覆盖认证授权测试、注入攻击测试、会话管理测试、业务逻辑测试（越权访问、支付漏洞、隐私泄露），确保安全测试的全面性。
- 实现模糊测试（Fuzzing），针对协议解析器、序列化/反序列化、输入处理模块，使用模糊测试工具（如libFuzzer、go-fuzz）发现崩溃、内存错误、逻辑漏洞。
- 开展安全代码审查，人工审查关键安全模块（认证授权、加密解密、会话管理、数据处理），识别逻辑漏洞、编码缺陷，提供安全改进建议。
8. 合规与隐私保护能力（必备）
- 掌握数据保护法规与标准，包括GDPR（欧盟通用数据保护条例）、个人信息保护法、网络安全法、等保2.0/3.0、ISO 27001、PCIDSS，能根据法规要求设计合规方案。
- 实现隐私保护机制，包括用户同意管理、数据最小化原则、数据可携带权、被遗忘权、数据处理活动记录，确保符合隐私保护法规要求。
- 设计并实现数据分类分级，根据数据敏感度（绝密、机密、内部、公开）制定不同的保护策略，确保核心数据的重点保护。
- 实现数据跨境传输合规，评估跨境传输风险，采取安全保障措施（如标准合同条款、绑定公司规则、认证机制），确保符合数据跨境传输法规。
- 开展合规性审计与评估，准备合规文档（安全策略、数据处理协议、影响评估报告），配合监管机构检查，确保持续合规。
9. 安全架构与风险评估能力（必备）
- 掌握安全架构设计原则，包括纵深防御、最小权限、零信任、安全默认、开闭安全，能设计并评审安全架构方案，确保安全与业务的平衡。
- 开展安全风险评估，识别资产、威胁、漏洞、风险，使用STRIDE、威胁建模等方法论，系统化分析安全风险，制定风险应对策略（降低、转移、接受、规避）。
- 设计并实现安全边界划分，包括网络隔离（VLAN、子网、防火墙）、服务隔离（微服务隔离、容器隔离）、数据隔离，减少攻击面，限制安全事件的影响范围。
- 实现安全监控与响应体系，包括入侵检测系统（IDS）、入侵防御系统（IPS）、SIEM（安全信息与事件管理）、SOAR（安全编排自动化与响应），建立安全事件响应流程（检测、分析、遏制、根除、恢复）。
10. DevSecOps与安全左移能力（必备）
- 掌握DevSecOps理念，将安全集成到DevOps全流程（需求、设计、开发、测试、部署、运维），实现安全左移，在开发阶段发现并修复安全问题。
- 实现安全CI/CD集成，将安全扫描（SAST、SCA、容器扫描）嵌入CI流水线，实现自动化的安全检查，阻止有漏洞的代码部署到生产环境。
- 推动安全培训与意识提升，定期开展安全培训（安全编码、安全意识、社会工程学防范），组织钓鱼邮件模拟演练，提升团队安全意识。
- 建立安全度量指标，包括漏洞修复时效、安全测试覆盖率、安全事件响应时间、合规性得分，量化安全工作成效，持续改进安全体系。
二、使用场景（全场景覆盖，聚焦安全核心）
1. 基础使用场景
- 设计并实现数据加密方案，确保敏感数据（用户密码、个人信息、业务数据）的存储与传输安全。
- 设计并实现身份认证与访问控制体系，确保用户身份可信、权限合理，防范越权访问。
- 基于TLS实现安全通信，确保网络传输的机密性与完整性，防范中间人攻击。
- 实现安全编码规范，指导开发团队编写安全代码，避免常见安全漏洞。
- 开展安全测试（SAST、DAST、渗透测试），发现并修复安全漏洞，提升系统安全性。
2. 扩展使用场景
- 针对分布式系统设计安全架构，实现零信任网络、微隔离、服务间安全通信（mTLS、Service Mesh）。
- 针对云原生环境设计容器安全（镜像扫描、运行时安全、网络策略），实现K8s安全配置（RBAC、Network Policy、Pod Security Policy）。
- 针对合规要求开展安全合规评审，确保符合等保2.0/3.0、GDPR、个人信息保护法等法规标准。
- 推动DevSecOps落地，将安全集成到CI/CD流水线，实现自动化安全扫描与漏洞修复。
- 开展安全事件响应与应急演练，建立安全事件响应流程，提升安全事件处置能力。
三、典型评审要点（全维度、可落地，聚焦安全核心）
1. 数据安全评审（核心评审点）
- 数据加密方案是否合理？敏感数据是否加密存储（数据库、文件、日志），加密算法选型是否正确，密钥管理是否安全？
- 数据传输是否使用TLS？TLS版本是否为1.2/1.3，加密套件是否安全，证书是否有效，是否防范中间人攻击？
- 数据脱敏是否到位？敏感数据（日志、调试信息、错误信息）是否脱敏，是否泄露隐私信息？
- 密钥管理是否符合最佳实践？密钥是否硬编码，是否定期轮换，是否使用HSM/KMS，密钥访问是否有审计？
- 数据分类分级是否清晰？是否根据数据敏感度制定不同的保护策略，核心数据是否有额外保护措施？
2. 访问控制与身份认证评审（核心评审点）
- 身份认证机制是否安全？是否支持MFA、强密码策略，密码存储是否使用慢哈希（bcrypt/Argon2），是否防范暴力破解？
- 访问控制模型是否合理？是否实现最小权限原则、职责分离，是否存在越权访问风险？
- 会话管理是否安全？会话是否安全生成（随机、足够长度），是否安全传输（HttpOnly、Secure Cookie），是否支持会话失效、单点登出？
- API鉴权是否完善？API Key/Token是否安全签发、验证、刷新、撤销，是否防范Token泄露、重放攻击？
- 权限变更是否有审计？权限变更操作是否记录日志，是否支持权限追溯与回滚？
3. 通信安全评审（核心评审点）
- TLS实现是否规范？TLS版本是否为1.2/1.3，是否禁用过时版本（TLS 1.0/1.1），加密套件是否安全（是否禁用弱加密套件）？
- 证书管理是否规范？证书是否有效（未过期、未吊销），证书链是否完整，是否支持自动续期（Let's Encrypt、ACME）？
- mTLS是否实现？双向认证是否落地，客户端证书是否验证，是否适配零信任网络场景？
- TLS性能是否优化？是否使用Session Ticket、Session Resumption、False Start，减少TLS握手延迟？
- 通信安全漏洞是否修复？是否存在中间人攻击风险、降级攻击风险、 renegotiation漏洞？
4. 漏洞防护评审（必备评审点）
- 注入攻击防护是否到位？是否使用参数化查询、输入验证、输出编码，是否防范SQL注入、NoSQL注入、命令注入？
- XSS防护是否到位？是否实现输出编码、CSP、输入验证，是否防范反射型、存储型、DOM型XSS？
- CSRF防护是否到位？是否使用CSRF Token、SameSite Cookie、Referer校验，状态变更操作是否防范CSRF？
- 安全配置是否正确？是否配置安全Headers（CSP、X-Frame-Options、X-Content-Type-Options），Cookie属性是否安全（HttpOnly、Secure、SameSite）？
- 依赖库漏洞是否修复？是否定期扫描第三方依赖（npm audit、go mod audit），是否及时更新有漏洞的依赖库？
- 反序列化漏洞是否防范？是否使用白名单校验、输入验证，是否防范不安全反序列化导致的RCE？
5. 安全审计与日志监控评审（必备评审点）
- 安全审计日志是否完整？关键安全事件（登录、登出、权限变更、敏感操作）是否记录，日志是否包含必要上下文（时间、用户、IP、操作结果）？
- 日志脱敏是否到位？敏感信息（密码、Token、身份证号）是否从日志中脱敏，是否防范日志泄露隐私？
- 日志访问是否受控？日志访问权限是否受限，是否防范日志被恶意篡改、删除，是否支持日志完整性校验？
- 安全监控告警是否健全？异常安全事件（多次登录失败、异常IP访问、高频API调用）是否实时告警，是否联动响应机制？
- 安全事件溯源是否可行？日志是否支持关联分析、用户行为分析，是否能快速定位根因、提供证据链？
6. 安全编码评审（必备评审点）
- 输入验证是否到位？用户输入是否验证（类型、长度、格式、范围），是否防范恶意输入、超长输入、特殊字符？
- 输出编码是否正确？动态内容是否正确编码（HTML编码、JavaScript编码、URL编码），是否防范XSS？
- 错误处理是否安全？错误信息是否泄露敏感数据，是否统一错误码体系，是否防范信息泄露？
- 并发安全是否考虑？是否存在竞态条件、死锁、数据竞争，是否使用安全的并发原语（锁、通道、原子操作）？
- 密码存储是否安全？是否使用bcrypt/scrypt/Argon2加盐存储，是否防范彩虹表攻击、暴力破解？
7. 安全测试评审（必备评审点）
- 安全测试是否全面？是否开展SAST、DAST、渗透测试、模糊测试，覆盖OWASP Top 10漏洞？
- 安全测试工具是否到位？是否使用SonarQube、OWASP ZAP、Burp Suite、Gosec等工具，是否集成到CI/CD流水线？
- 安全测试用例是否完整？是否覆盖认证授权、注入攻击、会话管理、业务逻辑（越权访问、支付漏洞）？
- 安全代码审查是否开展？是否人工审查关键安全模块，是否识别逻辑漏洞、编码缺陷？
- 安全漏洞修复是否及时？漏洞修复时效是否符合SLA，是否验证修复有效性，是否防范漏洞回归？
8. 合规与隐私保护评审（辅助评审点）
- 数据保护法规是否遵循？是否符合GDPR、个人信息保护法、网络安全法等法规要求？
- 隐私保护机制是否到位？是否实现用户同意管理、数据最小化、可携带权、被遗忘权？
- 数据分类分级是否清晰？是否根据数据敏感度制定保护策略，核心数据是否有重点保护？
- 数据跨境传输是否合规？是否评估跨境传输风险，是否采取安全保障措施？
- 合规审计是否通过？是否通过等保2.0/3.0、ISO 27001等合规评估，是否准备合规文档？
9. 安全架构与风险评估评审（辅助评审点）
- 安全架构设计是否合理？是否实现纵深防御、最小权限、零信任、安全默认，是否防范单点故障？
- 威胁建模是否开展？是否识别资产、威胁、漏洞，是否使用STRIDE等方法论，是否制定风险应对策略？
- 安全边界是否清晰？是否实现网络隔离、服务隔离、数据隔离，是否减少攻击面？
- 安全监控与响应体系是否完善？是否部署IDS/IPS、SIEM、SOAR，是否建立事件响应流程？
10. DevSecOps与安全左移评审（辅助评审点）
- 安全是否集成到DevOps？是否实现安全CI/CD集成，是否将安全扫描嵌入流水线？
- 安全培训是否开展？是否定期开展安全培训、钓鱼邮件演练，是否提升团队安全意识？
- 安全度量指标是否建立？是否量化安全工作成效（漏洞修复时效、安全测试覆盖率、响应时间）？
- 安全持续改进是否到位？是否根据安全事件、漏洞趋势优化安全策略，是否持续提升安全能力？
四、评审输出格式（标准化、可落地，适配安全场景）
评审输出需结构化、可执行，明确安全风险、加固建议、优先级，便于开发团队落地整改，具体包含以下7个部分：
1. 评审概况与评分
- 评审对象：明确评审的安全相关内容（如"数据加密方案""身份认证体系""TLS配置""漏洞扫描报告""合规评估"）
- 评审范围：覆盖的安全维度（数据安全、访问控制、通信安全、漏洞防护、审计合规等）
- 分维度评分（1-10分）：数据安全、认证授权、通信安全、漏洞防护、审计监控、安全编码、合规性
- 总分（1-10分）：基于分维度评分加权计算，明确评审结论（如"8分，数据加密、TLS配置到位，需完善API鉴权与日志审计""5分，存在SQL注入、XSS高危漏洞，需紧急修复"）
2. 具体问题列表（分类呈现）
按"严重程度+问题类型+具体描述+相关依据"分类，确保问题可定位、无歧义，严重程度分为4级：
- 致命问题：导致严重安全事故、数据泄露、系统被入侵（如密码明文存储、SQL注入漏洞、TLS未配置、硬编码密钥、无权限校验）
- 高风险问题：存在重大安全风险，可能被利用导致安全事故（如弱加密算法、会话劫持风险、XSS漏洞、依赖库有已知漏洞、日志泄露敏感信息）
- 中风险问题：安全加固不足，但暂无直接利用风险（如安全Headers缺失、Cookie属性不安全、错误信息泄露、安全测试未覆盖）
- 低风险问题：安全优化建议，不影响当前安全性，可后续迭代优化（如安全文档不完整、安全培训缺失、安全度量未建立）
示例：【致命-数据安全】用户密码使用SHA-1哈希存储，未加盐，易被彩虹表攻击破解，相关依据：代码扫描报告第3页（password_hash.go:45）
3. 改进建议（分优先级）
按"紧急修复+安全加固+持续改进"分类，每个建议对应具体问题，明确整改方向、操作步骤，可落地、可验证：
- 紧急修复（上线前必须完成）：针对致命、高风险问题，给出具体整改方案（如"使用bcrypt+盐存储用户密码；修复SQL注入漏洞，使用参数化查询；配置TLS 1.3，禁用弱加密套件"）
- 安全加固（迭代中逐步完成）：针对中风险问题，加强安全防护（如"添加安全Headers（CSP、X-Frame-Options）；设置Cookie安全属性（HttpOnly、Secure、SameSite）；对日志敏感信息脱敏"）
- 持续改进（体系优化）：针对低风险问题，完善安全体系（如"完善安全文档，建立安全编码规范；开展安全培训，提升安全意识；建立安全度量指标，量化安全成效"）
4. 操作示例（正反例对比）
针对核心问题，提供错误操作与正确操作的对比，便于开发团队快速理解、整改，示例：
- 错误操作（密码存储）：使用SHA-1哈希存储用户密码，未加盐，哈希值为"5f4dcc3b5aa765d61d8327deb882cf99"
- 正确操作：使用bcrypt+随机盐存储密码，盐值存储为"$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"，哈希值包含算法标识、成本因子、盐值、哈希值，防范彩虹表攻击
- 错误操作（SQL查询）：拼接SQL语句，直接使用用户输入："SELECT * FROM users WHERE username='" + username + "'"
- 正确操作：使用参数化查询，避免SQL注入："SELECT * FROM users WHERE username=?", username作为参数传递
5. 风险评估与合规分析（如适用）
针对安全问题进行风险评估，分析可能的影响与合规风险，示例：
- 风险等级：高危（CVSS评分7.5），SQL注入可能导致数据库被拖库，用户数据全部泄露
- 影响范围：所有用户数据（用户名、密码哈希、个人信息），约100万用户受影响
- 合规风险：违反个人信息保护法、网络安全法，可能面临监管处罚、用户索赔
- 整改价值：修复SQL注入后，消除数据库拖库风险，避免数据泄露，保障用户隐私，符合法规要求
6. 落地优先级
明确问题整改的顺序，优先保障核心安全、数据安全、系统安全，优先级排序原则：
- 第一优先级：致命问题（导致严重安全事故、数据泄露、系统被入侵）
- 第二优先级：高风险问题（存在重大安全风险，可能被利用导致安全事故）
- 第三优先级：中风险问题（安全加固不足，但暂无直接利用风险）
- 第四优先级：低风险问题（安全优化建议，可后续迭代完善）
7. 风险提示
明确未修复问题可能导致的安全风险、业务风险、合规风险，便于团队重视，示例：
- 若不修复"密码明文存储"问题，将导致数据库被拖库后用户密码直接泄露，攻击者可直接登录用户账户，造成财产损失、隐私泄露，面临巨额赔偿与监管处罚。
- 若不修复"SQL注入漏洞"，攻击者可通过注入恶意SQL语句获取数据库所有数据，包括用户信息、订单信息、支付信息，造成数据泄露、财产损失，严重损害企业声誉。
- 若不配置TLS，通信数据明文传输，攻击者可通过中间人攻击获取所有传输数据（包括密码、Token、个人信息），无法保障数据机密性，违反数据保护法规。
