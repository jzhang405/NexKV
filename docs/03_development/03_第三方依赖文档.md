## 📦 直接依赖

### 1. logrus - 日志库

**包路径**: `github.com/sirupsen/logrus`
**版本**: `v1.9.4`
**许可证**: MIT
**用途**: 结构化日志记录

#### 功能特性

- **结构化日志**: 支持 JSON 和文本格式
- **日志级别**: Trace、Debug、Info、Warn、Error、Fatal、Panic
- **钩子机制**: 支持自定义日志钩子
- **字段日志**: 支持 `WithFields` 结构化字段

#### 使用示例

```go
import "github.com/sirupsen/logrus"

logger := logrus.New()
logger.SetLevel(logrus.InfoLevel)
logger.SetFormatter(&logrus.JSONFormatter{})

logger.WithFields(logrus.Fields{
    "node_id": "node-1",
    "shard_id": "shard-1",
}).Info("Shard created successfully")
```

#### 配置建议

| 场景 | 日志级别 | 格式 | 输出 |
|------|---------|------|------|
| **开发环境** | Debug | Text | stdout |
| **生产环境** | Info | JSON | 文件 + stderr |
| **性能测试** | Warn | Text | /dev/null |

#### 替代方案考虑

当前使用 **logrus** 而非 **zap** 的原因：
- ✅ API 简单，易于上手
- ✅ 兼容性好，社区成熟
- ⚠️ 性能略低于 zap（零分配场景）

**未来迁移路径**: 如需极致性能，可迁移到 `go.uber.org/zap`

### 2. viper - 配置管理

**包路径**: `github.com/spf13/viper`
**版本**: `v1.21.0`
**许可证**: MIT
**用途**: 配置文件解析和管理

#### 功能特性

- **多格式支持**: YAML、JSON、TOML、HCL
- **多来源**: 文件、环境变量、命令行参数、远程配置中心
- **热更新**: 支持配置重载（`WatchConfig`）
- **默认值**: 支持设置默认值
- **参数绑定**: 支持绑定到结构体

#### 使用示例

```go
import "github.com/spf13/viper"

viper.SetConfigName("config")
viper.SetConfigType("yaml")
viper.AddConfigPath("./configs")
viper.AddConfigPath("/etc/nexkv")

if err := viper.ReadInConfig(); err != nil {
    log.Fatalf("Failed to read config: %v", err)
}

var config Config
if err := viper.Unmarshal(&config); err != nil {
    log.Fatalf("Failed to unmarshal config: %v", err)
}
```

#### 配置优先级

从高到低：
1. 显式设置（`viper.Set`）
2. 命令行参数（`pflag`）
3. 环境变量
4. 配置文件
5. 默认值

### 3. testify - 测试框架

**包路径**: `github.com/stretchr/testify`
**版本**: `v1.11.1`
**许可证**: MIT
**用途**: 单元测试和断言

#### 功能特性

- **断言库**: 丰富的断言函数（`assert` 包）
- **Mock 支持**: 接口 Mock（`mock` 包）
- **测试套件**: 测试组织和共享 Fixture（`suite` 包）
- **HTTP 测试**: HTTP 响应测试（`http` 包）

#### 使用示例

```go
import (
    "testing"
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/mock"
    "github.com/stretchr/testify/suite"
)

// 基本断言
func TestSomething(t *testing.T) {
    assert.Equal(t, 123, getValue())
    assert.NoError(t, doSomething())
    assert.True(t, isValid())
}

// Mock 对象
type MockTransport struct {
    mock.Mock
}

func (m *MockTransport) Send(addr string, data []byte) error {
    args := m.Called(addr, data)
    return args.Error(0)
}

// 测试套件
type MVStoreTestSuite struct {
    suite.Suite
    store *MVStore
}

func (s *MVStoreTestSuite) SetupTest() {
    s.store = NewMVStore()
}

func (s *MVStoreTestSuite) TearDownTest() {
    s.store.Close()
}

func (s *MVStoreTestSuite) TestPutAndGet() {
    s.store.Put("key", []byte("value"))
    value, err := s.store.Get("key")
    s.NoError(err)
    s.Equal([]byte("value"), value)
}
```

#### 断言函数清单

| 函数 | 说明 |
|------|------|
| `assert.Equal(t, expected, actual)` | 相等断言 |
| `assert.NoError(t, err)` | 无错误断言 |
| `assert.True(t, condition)` | 真值断言 |
| `assert.Len(t, obj, length)` | 长度断言 |
| `assert.Contains(t, collection, element)` | 包含断言 |
| `assert.Panics(t, func())` | 异常断言 |
| `assert.InDelta(t, expected, actual, delta)` | 浮点数断言 |

testify 引入以下间接依赖：

**许可证**: BSD-2-Clause
**用途**: MessagePack 二进制序列化

##### 特性

- **高性能**: 比 JSON 快 2-3 倍
- **紧凑**: 体积比 JSON 小 30%
- **无需 IDL**: 直接序列化 Go 结构体

##### 使用示例

```go
import "github.com/vmihailenco/msgpack/v5"

// 序列化
data, err := msgpack.Marshal(&Message{
    Type:    MessageTypeShardCreate,
    ShardID: "shard-1",
})

// 反序列化
var msg Message
err = msgpack.Unmarshal(data, &msg)
```

## 🔒 安全考虑

### 已知漏洞扫描

使用 `go list -json -m all | nancy sleuth` 定期扫描已知漏洞：

```bash
# 安装 nancy
go install github.com/sonatypecommunity/nancy@latest

# 扫描依赖
go list -json -m all | nancy sleuth
```

### 依赖安全最佳实践

| 实践 | 说明 |
|------|------|
| **定期更新** | 每月检查依赖更新，修复安全漏洞 |
| **固定版本** | 使用 `go.mod` 固定版本，避免意外更新 |
| **CI 集成** | 在 CI 流水线中集成安全扫描 |
| **审查代码** | 引入新依赖前审查其代码质量 |
| **最小依赖** | 仅引入必需的依赖，避免依赖膨胀 |

### 安全更新流程

1. **发现漏洞**: 通过安全扫描或官方公告
2. **评估影响**: 确认漏洞是否影响项目
3. **查找修复**: 检查是否有修复版本
4. **测试验证**: 在测试环境验证新版本
5. **更新部署**: 更新 `go.mod` 并重新部署

## 🚀 依赖升级策略

### 语义化版本规则

| 版本变更类型 | 说明 | 手动测试要求 |
|------------|------|-------------|
| **Patch (x.x.PATCH)** | Bug 修复，向后兼容 | 低 |
| **Minor (x.MINOR.x)** | 新功能，向后兼容 | 中 |
| **Major (MAJOR.x.x)** | 可能破坏向后兼容 | 高 |

### 升级流程

```bash
# 1. 检查可用更新
go list -u -m all

# 2. 更新特定依赖
go get github.com/sirupsen/logrus@v1.9.5

# 3. 更新所有依赖（谨慎）
go get -u ./...

# 4. 清理未使用的依赖
go mod tidy

# 5. 验证依赖
go mod verify

# 6. 运行测试
go test ./...

# 7. 提交变更
git add go.mod go.sum
git commit -m "chore: upgrade logrus to v1.9.5"
```

### 自动化依赖更新

使用 `Renovate` 或 `Dependabot` 自动创建 PR：

**`.github/renovate.json`**:
```json
{
  "extends": ["config:base"],
  "schedule": ["monthly"],
  "commitMessagePrefix": "chore(deps):",
  "labels": ["dependencies"],
  "reviewers": ["team:maintainers"],
  "packageRules": [
    {
      "matchUpdateTypes": ["minor", "patch"],
      "automerge": true
    },
    {
      "matchUpdateTypes": ["major"],
      "automerge": false
    }
  ]
}
```

## 🔍 常见问题

### Q1: 为什么选择 logrus 而非 zap？

**A**: logrus API 简单，社区成熟，适合快速开发。zap 性能更优，未来可迁移。

### Q2: 间接依赖太多怎么办？

**A**: 间接依赖是必要的，Go Modules 会自动管理。使用 `go mod tidy` 清理未使用的依赖。

### Q3: 如何安全地更新依赖？

**A**:
1. 查看更新日志（CHANGELOG）
2. 更新特定版本（`go get package@version`）
3. 运行测试确保兼容性
4. 提交 PR 并 Code Review

### Q4: 许可证冲突怎么办？

**A**: 所有当前依赖都是宽松许可证，与 AGPL-3.0 兼容。引入新依赖前检查许可证。
