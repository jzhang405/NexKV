## 3. 配置说明

### 3.1 配置文件结构

**config.yaml**:
```yaml
# 集群配置
cluster:
  name: "nexkv-cluster"
  node:
    id: "node-1"          # 节点 ID(唯一)
    addr: "0.0.0.0:9211"  # 监听地址
  seed_nodes:
    - "node-1:9211"
    - "node-2:9211"
    - "node-3:9211"
  mode: "cluster"         # standalone | cluster

# 元数据配置
metadata:
  dir: "./data/metadata"
  gossip_interval: "10s"
  quorum_timeout: "30s"
  cache_size: 10000

# 存储配置
storage:
  data_dir: "./data/shards"
  wal_dir: "./data/wal"
  snapshot_interval: "1h"
  # WAL 保留时间（双层 WAL 架构）
  metadata_wal_retention: "720h"    # 元数据 WAL：30 天
  business_wal_retention: "2160h"   # 业务 WAL：90 天（3个月）

# 网络配置
network:
  listen_addr: "0.0.0.0:9211"
  max_connections: 1000
  keepalive_interval: "30s"
  read_timeout: "30s"
  write_timeout: "30s"

# 日志配置
logging:
  level: "info"            # debug | info | warn | error
  format: "json"           # json | text
  output: "./logs/nexkv.log"
  max_size: 100            # MB
  max_backups: 10
  max_age: 30              # days
```

### 3.4 libp2p Transport 配置

NexKV 支持 libp2p Transport，提供 P2P 网络能力。libp2p 使用 **multiaddr** 格式表示节点地址，比传统的 `IP:PORT` 格式更加灵活和可扩展。

#### 3.4.1 multiaddr 地址格式

**multiaddr 格式**：
```
/ip4/192.168.1.1/tcp/4001/p2p/12D3KooW...
/dns4/node1.example.com/tcp/4001/p2p/12D3KooW...
```

**格式说明**：
- `/ip4/x.x.x.x` 或 `/dns4/hostname`：网络地址
- `/tcp/port`：传输协议和端口
- `/p2p/PeerID`：libp2p 节点 ID（从公钥派生）

#### 3.4.2 libp2p 完整配置

**libp2p.yaml**:
```yaml
# libp2p Transport 配置（完整版）
p2p:
  # 监听地址（multiaddr 格式）
  listen_addr: "/ip4/0.0.0.0/tcp/4001"

  # 私钥文件路径（必填）
  private_key_path: "/var/lib/nexkv/libp2p_key"

  # 连接管理器配置
  connection_manager:
    low_water: 100      # 最小连接数
    high_water: 400     # 最大连接数

  # 节点发现配置
  discovery:
    # mDNS 本地发现（局域网自动发现）
    mdns_enabled: true
    mdns_service_tag: "nexkv-discovery"

    # DHT 分布式哈希表（广域网发现）
    dht_enabled: true
    dht_bootstrap_peers: []

  # Bootstrap 节点（可选）
  bootstrap_peers:
    - "/ip4/192.168.1.10/tcp/4001/p2p/QmPeerID1..."
    - "/ip4/192.168.1.11/tcp/4001/p2p/QmPeerID2..."
    - "/ip4/192.168.1.12/tcp/4001/p2p/QmPeerID3..."

  # 超时配置
  timeouts:
    dial: "30s"           # 拨号超时
    connection: "60s"     # 连接超时
    stream: "30s"         # 流超时
```

#### 3.4.3 libp2p 最小配置

**libp2p-minimal.yaml**:
```yaml
# libp2p 最小配置（仅必填字段）
p2p:
  listen_addr: "/ip4/0.0.0.0/tcp/4001"
  private_key_path: "/var/lib/nexkv/libp2p_key"
```

**配置说明**：
- `listen_addr`：监听地址，必须使用 multiaddr 格式
- `private_key_path`：私钥文件路径，首次运行会自动生成

#### 3.4.4 从传统配置迁移到 libp2p

**旧格式**（TCP/UDP）：
```yaml
cluster:
  name: "nexkv-cluster"
  node:
    id: "node-1"
    addr: "192.168.1.10:9211"
  seed_nodes:
    - "192.168.1.10:9211"
    - "192.168.1.11:9211"
```

**新格式**（libp2p）：
```yaml
p2p:
  listen_addr: "/ip4/192.168.1.10/tcp/4001"
  private_key_path: "/var/lib/nexkv/libp2p_key"
  bootstrap_peers:
    - "/ip4/192.168.1.10/tcp/4001/p2p/QmPeerID1..."
    - "/ip4/192.168.1.11/tcp/4001/p2p/QmPeerID2..."
```

**迁移步骤**：
1. 备份现有配置和数据
2. 生成 libp2p 密钥对（或使用现有的）
3. 更新配置文件格式
4. 验证配置并重启节点

**详细迁移指南**：参见 [docs/migration/libp2p.md](../migration/libp2p.md)

#### 3.4.5 配置验证

```bash
# 使用配置验证工具
./bin/nexkv -config /path/to/config.yaml -validate

# 查看解析后的配置
./bin/nexkv -config /path/to/config.yaml -show-config
```

**验证清单**：
- [ ] `listen_addr` 是有效的 multiaddr 格式
- [ ] `private_key_path` 路径存在且可访问
- [ ] `bootstrap_peers` 中的地址包含有效的 PeerID
- [ ] 端口未被防火墙阻止
- [ ] 如果使用 DHT，网络可达性正常

## 4. 部署方式

### 4.1 本地开发环境部署

#### macOS

```bash
# 1. 编译项目
cd /path/to/NexKV
make build

# 2. 创建数据目录
mkdir -p data/{metadata,shards,wal}
mkdir -p logs

# 3. 启动单机模式
./bin/nexkv -config configs/single_node.yaml

# 4. 使用 CLI 连接
./bin/nexkv-cli -addr 127.0.0.1:9211 cluster list

# 5. 后台运行
nohup ./bin/nexkv -config configs/single_node.yaml > logs/nexkv.log 2>&1 &
```

---

#### Linux

```bash
# 1. 创建目录
mkdir -p /opt/nexkv/{bin,conf,data,logs}

# 2. 复制二进制
cp bin/nexkv /opt/nexkv/bin/
cp bin/nexkv-cli /opt/nexkv/bin/

# 3. 复制配置
cp configs/config.yaml /opt/nexkv/conf/

# 4. 创建用户
sudo useradd -r -s /bin/false nexkv
sudo chown -R nexkv:nexkv /opt/nexkv

# 5. 启动服务
sudo -u nexkv /opt/nexkv/bin/nexkv -config /opt/nexkv/conf/config.yaml
```

---

### 4.2 Systemd 服务 (Linux 生产环境)

#### 传统 TCP Transport 配置

**/etc/systemd/system/nexkv.service**:
```ini
[Unit]
Description=NexKV Distributed KV Store
After=network.target

[Service]
Type=simple
User=nexkv
Group=nexkv
ExecStart=/opt/nexkv/bin/nexkv -config /opt/nexkv/conf/config.yaml
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

#### libp2p Transport 配置

**/etc/systemd/system/nexkv.service**:
```ini
[Unit]
Description=NexKV Distributed KV Store (libp2p)
After=network.target
Wants=network-online.target

[Service]
Type=simple
User=nexkv
Group=nexkv
ExecStart=/opt/nexkv/bin/nexkv -config /opt/nexkv/conf/libp2p.yaml
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

# libp2p 需要更长的启动时间
TimeoutStartSec=60

[Install]
WantedBy=multi-user.target
```

**启动服务**:
```bash
# 重载 systemd
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start nexkv

# 开机自启
sudo systemctl enable nexkv

# 查看状态
sudo systemctl status nexkv

# 查看日志
sudo journalctl -u nexkv -f
```

## 6. 升级指南

### 6.1 滚动升级

```bash
# 1. 备份数据
./bin/nexkv-cli -addr node-1:9211 snapshot create

# 2. 逐个节点升级
for node in node-1 node-2 node-3; do
  echo "Upgrading $node..."

  # 停止节点
  ssh $node "sudo systemctl stop nexkv"

  # 替换二进制
  scp bin/nexkv $node:/opt/nexkv/bin/nexkv.new
  ssh $node "mv /opt/nexkv/bin/nexkv /opt/nexkv/bin/nexkv.old"
  ssh $node "mv /opt/nexkv/bin/nexkv.new /opt/nexkv/bin/nexkv"

  # 启动节点
  ssh $node "sudo systemctl start nexkv"

  # 等待节点就绪
  sleep 10
done
```

## 7. 安全加固

### 7.1 TLS 配置

```yaml
# config.yaml
network:
  tls:
    enabled: true
    cert_file: "/opt/nexkv/certs/server.crt"
    key_file: "/opt/nexkv/certs/server.key"
    ca_file: "/opt/nexkv/certs/ca.crt"
    client_auth:
      enabled: true
      ca_file: "/opt/nexkv/certs/client-ca.crt"
```

**生成证书**:
```bash
# 生成 CA
openssl genrsa -out ca-key.pem 2048
openssl req -x509 -new -nodes -key ca-key.pem -sha256 -days 3650 -out ca.pem -subj "/CN=NexKV CA"

# 生成服务器证书
openssl genrsa -out server-key.pem 2048
openssl req -new -key server-key.pem -out server.csr -subj "/CN=nexkv-server"
openssl x509 -req -in server.csr -CA ca.pem -CAkey ca-key.pem -CAcreateserial -out server.crt -days 365

# 生成客户端证书
openssl genrsa -out client-key.pem 2048
openssl req -new -key client-key.pem -out client.csr -subj "/CN=nexkv-client"
openssl x509 -req -in client.csr -CA ca.pem -CAkey ca-key.pem -CAcreateserial -out client.crt -days 365
```

## 9. 故障排查

### 9.1 节点无法启动

**症状**: 服务启动失败

**排查步骤**:
```bash
# 1. 查看详细日志
sudo journalctl -u nexkv -n 50 --no-pager

# 2. 检查端口占用
sudo lsof -i :9211

# 3. 验证配置文件
./bin/nexkv -config /opt/nexkv/conf/config.yaml -validate

# 4. 检查权限
sudo chown -R nexkv:nexkv /opt/nexkv
```

### 9.2 节点无法加入集群

**症状**: 节点启动后无法被发现

**排查步骤**:
```bash
# 1. 检查网络连通性
ping seed-node-addr
telnet seed-node-addr 9211

# 2. 检查防火墙
sudo iptables -L -n | grep 9211

# 3. 检查配置
# cluster.seed_nodes 必须包含正确的种子节点地址

# 4. 查看日志
sudo journalctl -u nexkv -f | grep "seed node"
```

### 9.4 libp2p 专门问题排查

#### 9.4.1 节点无法发现其他节点

**症状**: mDNS 或 DHT 发现失败，节点无法自动发现对等节点

**排查步骤**:
```bash
# 1. 检查 mDNS 是否启用
sudo journalctl -u nexkv -f | grep "mDNS"

# 2. 验证 multiaddr 格式
# 正确格式: /ip4/x.x.x.x/tcp/port
# 错误格式: x.x.x.x:port

# 3. 检查防火墙（mDNS 需要 UDP 5353）
sudo ufw status | grep 5353
sudo firewall-cmd --list-ports | grep 5353

# 4. 检查节点是否在同一网络
ping <peer-ip>
```

**解决方案**:
- 确保防火墙允许 UDP 5353（mDNS）和配置的 TCP 端口
- 确认 `discovery.mdns_enabled: true`
- 验证 `listen_addr` 使用正确的 multiaddr 格式

#### 9.4.2 连接数超过限制

**症状**: 日志显示 "high water exceeded" 或 "connection limit reached"

**排查步骤**:
```bash
# 1. 查看当前连接数
sudo journalctl -u nexkv -f | grep "connection"

# 2. 检查配置
grep -A 3 "connection_manager" /opt/nexkv/conf/libp2p.yaml
```

**解决方案**:
- 调整 `connection_manager.high_water` 配置
```yaml
connection_manager:
  high_water: 500  # 增加最大连接数
```

#### 9.4.3 节点 ID 发生变化

**症状**: 节点重启后 PeerID 改变

**排查步骤**:
```bash
# 1. 检查密钥文件
ls -la /var/lib/nexkv/libp2p_key

# 2. 验证密钥文件未被重新生成
stat /var/lib/nexkv/libp2p_key
```

**解决方案**:
- 确保使用相同的密钥文件
- 检查 `private_key_path` 配置正确
- 验证文件权限正确

#### 9.4.4 配置验证失败

**症状**: 启动时提示 "invalid multiaddr format"

**常见错误**:
- `invalid multiaddr format`：使用 `/ip4/x.x.x.x/tcp/port` 格式
- `private_key_path is required`：必须指定私钥路径

**解决方案**:
```bash
# 1. 验证配置文件
./bin/nexkv -config /opt/nexkv/conf/libp2p.yaml -validate

# 2. 检查 multiaddr 格式
# 正确: /ip4/0.0.0.0/tcp/4001
# 错误: 0.0.0.0:4001

# 3. 确保私钥文件存在
test -f /var/lib/nexkv/libp2p_key || echo "密钥文件不存在"
```
