## 第二部分：简答题（4题，每题5分，共20分）

### 1. DDD 架构原则（5分）

**问题**: 请简述依赖倒置原则（DIP）在 NexKV 5层架构中的应用。

**答案**:
```
高层模块（API层、控制平面层）不依赖低层模块（存储引擎层、基础设施层）的具体实现，
而是依赖抽象接口。具体实现在 infrastructure 层实现 domain 层定义的接口。

示例：
- 控制平面层依赖 KVStore 接口（domain 层）
- infrastructure 层提供 KVStore 的具体实现（如 Bf-Tree、Badger）
- 通过依赖注入（Wire）将实现注入到高层模块
```

### 2. Go 泛型编程（5分）

**问题**: 请简述 AsyncOperation[T] 的三种模式及其应用场景。

**答案**:
```
1. Future 模式：
   - 异步操作返回 Future 对象
   - 调用方通过 Future.Get() 阻塞等待结果
   - 适用场景：需要同步等待结果的场景

2. Callback 模式：
   - 异步操作接收回调函数
   - 操作完成后自动调用回调
   - 适用场景：事件驱动、非阻塞场景

3. Channel 模式：
   - 异步操作返回 Channel
   - 调用方通过 Channel 接收结果
   - 适用场景：流式数据处理、事件流
```

### 3. libp2p 基础（5分）

**问题**: 请简述 NexKV 在局域网环境下使用 libp2p 的优势。

**答案**:
```
1. 去中心化：
   - 无需中心服务器
   - 节点间直接通信
   - 符合 NexKV 无中心架构

2. 局域网优化：
   - 使用 mDNS 进行节点发现
   - 无需 NAT 穿透
   - 低延迟、高吞吐

3. 协议栈完整：
   - 内置多种传输协议
   - Stream 多路复用
   - 加密通信

4. 易于扩展：
   - 保留接口层抽象
   - 未来可扩展到公网
```

---

### 4. Bf-Tree 原理（5分）

**问题**: 请简述 Bf-Tree 的性能优势来源和移植挑战。

**答案**:
```
性能优势来源：
1. 缓存友好设计：
   - 节点大小匹配 CPU 缓存行
   - 减少缓存未命中

2. WAL 优化：
   - 顺序写入
   - 减少磁盘寻道

3. 内存管理：
   - 内存快照
   - 减少锁竞争

移植挑战：
1. 语言差异：
   - Rust 的所有权系统 vs Go 的 GC
   - 需要重新设计内存管理

2. 并发模型：
   - Rust 的 async/await vs Go 的 goroutine
   - 需要适配 Go 的并发模型

3. 性能优化：
   - Go 的性能特性与 Rust 不同
   - 需要重新优化性能热点
```
