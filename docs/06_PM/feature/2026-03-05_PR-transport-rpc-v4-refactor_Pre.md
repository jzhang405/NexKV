### 2. 背景与目标（为什么更新）

#### 2.1 更新原因

- **触发因素**：
  - Phase 0 异步重构完成后，RPC层需要升级到V4异步管道架构
  - 发现当前实现存在并发安全问题和性能瓶颈
  - 需要统一Task模型，消除AsyncOp和Task双重模型

- **现状问题**：
  1. **并发安全问题**：AsyncOp回调存在持锁执行死锁风险
  2. **CPU亲和性失效**：PerCoreExecutor绑核实现有缺陷
  3. **内存泄漏风险**：pendingCalls超时未清理
  4. **架构割裂**：AsyncOp与V4 Task[Result]双重模型并存
  5. **并发控制复杂**：广播使用信号量+Submit双重控制

- **更新价值**：
  1. 通过专家审查确保技术方案的可行性和安全性
  2. 识别并修复P0级别并发安全问题，避免生产事故
  3. 统一架构模型，提升代码可维护性
  4. 优化性能，预计提升20-30%

#### 2.2 更新目标

1. **准确性**：
