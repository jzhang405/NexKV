## 4. 为什么效果不明显？

### 4.1 COW 方案未真正生效

**根本原因**：Phase 1-2 只是修改了 `LeafPage` 的接口，但 BTree 的核心流程 **还未集成** COW 方案：

**当前流程**（未使用 COW）：
```
BTree.Set
  → findLeafPage (找到路径)
  → copyPathShallow (复制路径)
  → finalizeDeepClone (深拷贝页面)
    → LeafPage.Clone()  ← 现在使用 COW
    → 创建 COWDeltaRef，共享 keys/values
  → CAS 更新根节点
```

**问题**：
1. `finalizeDeepClone` 调用 `LeafPage.Clone()` 后，立即使用新页面
2. 新页面被 CAS 后，下一次操作可能直接深拷贝
3. **没有多个页面共享同一个 COWDeltaRef 的场景**

### 4.2 测试场景偏差

**Baseline 测试场景**：
- 单次 Set 操作
- 每次操作都是独立的 CAS 流程
- **没有多个 Clone 共享同一数据的场景**

**COW 优势场景**（未测试）：
- 多个读者共享同一页面
- 多次 Clone 共享底层数据
- 增量模式（多次修改同一页面）

## 5. 结论与建议

### 5.1 当前结论

1. **功能实现正确** ✅
   - 所有 215 个测试通过
   - 并发安全验证通过
   - CloneDeep 独立性验证通过

2. **性能符合预期** ✅
   - Clone < 200 ns 目标达成
   - Update 性能极大提升（21.7 倍）
   - 单线程 Set 性能提升 7.2%

3. **效果不明显的原因** ⚠️
   - COW 方案未在 BTree 核心流程中集成
   - 测试场景未触发 COW 共享优势
   - 需要真实场景验证

- 预期：真正发挥 COW 优势

- 多次修改同一页面的场景
