## P0 问题（必须修复）

### [P0-1] 类型断言未检查导致的 panic 风险

**文件**: `internal/metadata/gossip/merkle_sync.go:377`

```go
logging.WithFields(map[string]interface{}{
    "to":            nodeID,
    "diff_ns_count": len(diffResponse["diff_namespaces"].(map[string][]string)),
    "response_size": len(responseBytes),
}).Info("已发送差异响应")
```

**问题**: 类型断言 `diffResponse["diff_namespaces"].(map[string][]string)` 没有进行 ok 检查，如果断言失败会导致 panic。

**修复建议**:

```go
diffNS, ok := diffResponse["diff_namespaces"].(map[string][]string)
if !ok {
    logging.WithField("to", nodeID).Error("diff_namespaces 类型断言失败")
    return
}
logging.WithFields(map[string]interface{}{
    "to":            nodeID,
    "diff_ns_count": len(diffNS),
    "response_size": len(responseBytes),
}).Info("已发送差异响应")
```

### [P0-2] 类型断言未检查导致的 panic 风险

**文件**: `internal/metadata/gossip/merkle_sync.go:333-334`

```go
peerNamespaceHashes, ok := payload["namespace_hashes"].(map[string]string)
if !ok {
    logging.WithField("error", "invalid namespace_hashes type").Error("peer payload 格式错误")
    return
}
```

**问题**: 虽然这里有 ok 检查（很好），但在 line 139 的 `SyncWithPeer` 方法中也有相同的断言但错误处理不一致。

**修复建议**: 确保所有类型断言都有 ok 检查，返回错误而非仅记录日志。

## P1 问题（应该修复）

### [P1-1] 占位符代码未标记为 TODO 或使用假数据接口

**文件**: `internal/metadata/gossip/merkle_sync.go:479`

```go
// 简化实现：发送所有 Keys（实际应只发送变化的）
// 生产环境中需要从 MetadataKV 查询实际变化
response.DiffNamespaces[ns] = []string{"key1", "key2"} // 占位符，实际应查询
```

**问题**:
1. 使用硬编码的假数据 `[]string{"key1", "key2"}` 会让代码看起来像已完成
2. 没有明确的接口定义应该如何获取真实的 key 列表

**修复建议**:

```go
// TODO: 从 MetadataKV 查询该 Namespace 下实际变化的 Keys
// 当前返回空列表，待实现增量 Key 检测逻辑
response.DiffNamespaces[ns] = []string{}
// 或者使用 panic("not implemented") 强制提醒实现
```

或者定义一个接口来解耦：

```go
// MetadataKeyProvider 提供 Key 查询接口
type MetadataKeyProvider interface {
    GetKeysInNamespace(ns string) ([]string, error)
    GetChangedKeysSince(ns string, version uint64) ([]string, error)
}

// 在 MerkleGossipSync 中持有此接口
type MerkleGossipSync struct {
    // ... 其他字段
    keyProvider MetadataKeyProvider
}
```

### [P1-2] `metadataKV` 字段未使用

**文件**: `internal/metadata/gossip/merkle_sync.go:30-32`

```go
type MerkleGossipSync struct {
    merkle      *kvstore.NamespacedMerkleTree
    metadataKV  *kvstore.MetadataKV  // 声明但从未使用
    transport   transport.Transport
    // ...
}
```

**问题**: `metadataKV` 被声明但从未使用，这表明应该用它来获取真实的 key 列表（见 P1-1）。

**修复建议**: 要么使用它来获取 key 列表，要么移除它。

### [P1-3] 并发安全性问题

**文件**: `internal/metadata/gossip/merkle_sync.go:469`

```go
response := &GossipDiffResponse{
    FromNodeID:      s.localNodeID,
    GlobalRootHash:  localGlobalRoot,
    NamespaceHashes: s.merkle.GetAllNamespaceRootHashes(), // 并发调用
    // ...
}
```

**问题**: 虽然 `GetAllNamespaceRootHashes()` 内部有读锁保护，但在构建响应期间，Merkle Tree 可能被其他 goroutine 修改，导致响应数据不一致。

**修复建议**: 在 `buildDiffResponse` 开始时获取快照，或者将整个响应构建过程加锁保护。

### [P1-4] 错误处理不一致

**文件**: `internal/metadata/gossip/merkle_sync.go:367-372`

```go
if err := s.transport.Send(nodeID, responseBytes); err != nil {
    logging.WithFields(map[string]interface{}{
        "to":   nodeID,
        "error": err.Error(),
    }).Error("发送差异响应失败")
    return  // 仅记录日志并返回，不向上传播错误
}
```

**问题**: 发送失败仅记录日志但不向上传播错误，调用者无法知道发送失败。

**修复建议**: 考虑是否需要重试机制，或者至少记录到统计信息中。

### [P1-5] 缺少超时控制

**文件**: `internal/metadata/gossip/merkle_sync.go:303-381`

```go
func (s *MerkleGossipSync) handleIncomingMessage(nodeID string, msg []byte) {
    // 整个过程没有超时控制
    // ...
    if err := s.transport.Send(nodeID, responseBytes); err != nil {
        // ...
    }
}
```

**问题**: 没有超时控制，可能导致阻塞。

**修复建议**: 添加 context 超时控制：

```go
func (s *MerkleGossipSync) handleIncomingMessage(nodeID string, msg []byte) {
    ctx, cancel := context.WithTimeout(s.ctx, 30*time.Second)
    defer cancel()

    // ... 使用 ctx 控制 Send 操作
}
```

### [P2-5] 重复的日志记录模式
