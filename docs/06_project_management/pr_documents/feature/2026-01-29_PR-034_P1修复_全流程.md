## 第一部分：Pre（前置规划）

### 1. 需求背景

PR-033 实现了 Cluster 层基于 Host 的基础架构，但在代码评审中发现 **3 个 P1 问题**需要修复：

| 问题 | 模块 | 影响 | 优先级 |
|------|------|------|--------|
| **P1-1** | PortAllocator | 重试机制使用修改后的 hostID 持久化，导致端口分配不一致 | P1 |
| **P1-2** | HostManager | UpdateHostStatus 并发更新问题 | P1 |
| **P1-3** | FailureDetector | UDP 探测不可靠（Write 成功 ≠ 服务可达） | P1 |

**为什么是 P1 而非 P0**：
- 不影响基本功能，但在特定场景下可能出现问题
- 没有数据损坏或安全风险
- 可以在后续 PR 中修复，但建议尽早修复

### 2. 问题分析

#### P1-1: PortAllocator 重试机制缺陷

**问题描述**：
```go
// 当前实现（有问题）
if conflict {
    // 端口已被占用，使用时间戳重试
    retryHostID := fmt.Sprintf("%s%s%d", hostID, retryHostIDSuffix, time.Now().UnixNano())
    return pa.AllocTCPPort(retryHostID)  // ❌ 使用修改后的 hostID
}
```

**问题根因**：
- 使用 `hostID + timestamp` 作为新的 hostID 进行重试
- 这会导致持久化的分配记录中，同一个原始 hostID 有多条记录
- 重启后无法正确恢复原始 hostID 的端口分配

**正确做法**：
```go
// 应该使用原始 hostID，递增端口号重试
if conflict {
    // 递增端口号，使用原始 hostID
    tcpPort++  // 从哈希值改为递增
    udpPort = tcpPort + 1
    // 持久化时仍使用原始 hostID 作为 key
}
```

**影响范围**：
- 端口冲突时自动重试分配
- 进程重启后端口分配恢复

#### P1-2: HostManager UpdateHostStatus 并发更新问题

**问题描述**：
```go
// 当前实现（有问题）
func (hm *HostManager) UpdateHostStatus(hostID string, status HostStatus, lastHeartbeat int64) error {
    host, err := hm.GetHost(hostID)  // 读取时有锁
    if err != nil {
        return err
    }

    // ❌ 这里没有锁保护，并发更新会导致数据竞争
    host.HostStatus = status
    host.LastHeartbeat = lastHeartbeat

    return hm.AddHost(host)  // 写入时有锁
}
```

**问题根因**：
- `GetHost` 返回的是 Host 对象的指针
- 在无锁的情况下修改 Host 对象的字段
- 多个 goroutine 并发调用 `UpdateHostStatus` 会导致数据竞争

**正确做法**：
```go
func (hm *HostManager) UpdateHostStatus(hostID string, status HostStatus, lastHeartbeat int64) error {
    hm.mu.Lock()
    defer hm.mu.Unlock()

    host, exists := hm.hosts[hostID]
    if !exists {
        return types.NewClusterHostNotFoundError(hostID)
    }

    // 在锁保护下更新
    host.HostStatus = status
    host.LastHeartbeat = lastHeartbeat

    return nil
}
```

**影响范围**：
- 并发更新 Host 状态
- 多个 goroutine 同时更新心跳或状态

#### P1-3: FailureDetector UDP 探测不可靠

**问题描述**：
```go
// 当前实现（有问题）
udpConn, err := net.DialTimeout("udp", udpAddr, fd.config.ProbeTimeout)
if err == nil {
    // 尝试发送一个小数据包
    _, err = udpConn.Write([]byte("ping"))
    if err == nil {
        result.UDPReachable = true  // ❌ Write 成功不代表服务可达
    }
    udpConn.Close()
}
```

**问题根因**：
- UDP 是无连接协议，`Write` 只是把数据包发送到网络层
- `Write` 成功不代表数据包被服务接收（可能被防火墙丢弃、服务未监听等）
- 需要尝试读取响应，但当前实现没有读取逻辑

**正确做法**：
```go
// 方案 1：移除 UDP 探测（推荐）
// TCP 探测已经足够可靠（连接性 + 时延）
// UDP 探测在这个场景下没有实际意义

// 方案 2：完整实现 UDP 探测（需要服务端配合）
// 1. 发送 ping 消息
// 2. 等待 pong 响应（需要服务端实现 UDP ping/pong 协议）
// 3. 超时判定为不可达
```

**推荐方案**：
- 移除 UDP 探测，只保留 TCP 探测
- 理由：TCP 探测已经能验证连接性和时延，UDP 探测在当前架构下没有额外价值

**影响范围**：
- 故障检测逻辑
- `ProbeResult` 结构体（移除 `UDPReachable` 字段）

### 3. 设计方案

#### 3.1 PortAllocator 重试机制修复

**设计目标**：
- 使用原始 hostID 作为持久化 key
- 端口冲突时递增端口号重试
- 确保重启后端口分配一致性

**实现方案**：
```go
// 修改前
if conflict {
    retryHostID := fmt.Sprintf("%s%s%d", hostID, retryHostIDSuffix, time.Now().UnixNano())
    return pa.AllocTCPPort(retryHostID)
}

// 修改后
if conflict {
    // 递增端口号，直到找到可用端口
    for tcpPort++; tcpPort <= maxTCPPort; tcpPort++ {
        conflict, _, _ := pa.checkPortConflict(tcpPort)
        if !conflict {
            udpPort = tcpPort + 1
            break
        }
    }

    if tcpPort > maxTCPPort {
        return 0, 0, types.NewClusterPortExhaustedError()
    }

    // 持久化时仍使用原始 hostID 作为 key
    allocation := &PortAllocation{
        HostID:      hostID,  // 使用原始 hostID
        TCPPort:     tcpPort,
        UDPPort:     udpPort,
        AllocatedAt: time.Now().Unix(),
    }
}
```

**测试用例**：
- `TestPortAllocator_RetryWithOriginalHostID`：验证重试时使用原始 hostID
- `TestPortAllocator_PortExhaustion`：验证端口耗尽时的错误处理

#### 3.2 HostManager 并发更新修复

**设计目标**：
- 在锁保护下完成整个更新流程
- 避免数据竞争
- 保持 API 接口不变

**实现方案**：
```go
func (hm *HostManager) UpdateHostStatus(hostID string, status HostStatus, lastHeartbeat int64) error {
```

```go
type ProbeResult struct {
```
