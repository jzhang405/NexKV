## 一、Checkpoint 时序（Fuzzy Checkpoint v2）

Phase 4.3 扩展现有 `FuzzyCheckpoint` 增加 AO 页面刷新（对齐原始 spike §5.2 T0-T7）：

```
T0: checkpointStartLSN = wal.CurrentLSN()           ← 必须在 root snapshot 之前
T1: rootRef = btree.RootPage()                      ← COW 根快照
T2: items = btree.EnumeratePages(rootRef)            ← 后序遍历，子页面先于父页面
T3: 对每个 PageFlushItem:
      ├─ ChunkPos == 0（脏页）→ cm.Allocate + cm.WritePage（预序列化 PageData）
      └─ ChunkPos != 0（已持久化）→ 跳过
T4: cm.Sync()                                       ← 所有 chunk 文件 fsync
T4a: pageLocs 批量更新                               ← AO Sync 后、WAL Append 前（安全窗口）
T5: WAL.Append(CheckpointEntryV2)                    ← checkpointStartLSN + rootPageID + pageLocs
T6: WAL.Sync()
T7: WAL.Truncate(checkpointStartLSN)                 ← 丢弃已持久化的旧 WAL
```

### 1.1 WALTypeCheckpointV2 向后兼容

现有 `WALTypeCheckpoint` (type=5) 的 Key 为固定 8 字节（LSN）。Phase 4 扩展为可变长 Key 包含 `pageLocs` 映射。

```
CheckpointEntryV2:
  Type: WALTypeCheckpointV2 = 7 (新增类型码; 6 已被 WALTypeSplit 占用)
  Key: [FormatVersion:1][RootPageID:8][PageCount:4][(PageID:8, ChunkPos:8)*N]
       FormatVersion = 0x04 (Phase 4), 0x03 (Phase 3 legacy)
```

**兼容策略**：
1. `recovery.go` 检查 `Key[0]`:
   - `== 0x04` → Phase 4 格式，解析 pageLocs
   - `== 0x03` 或无前缀且 `len(Key) == 8` → Phase 3 格式（仅 startLSN）
2. 格式版本字节（FormatVersion prefix）比长度检测更可靠，避免虚假匹配
3. Phase 3 旧格式的 Recovery 不加 pageLocs，全量 WAL 重放
4. `service.WALType` 和 `wal.WALType` 需同步添加 `WALTypeCheckpointV2 = 7`

## 二、代码改动清单（5 个集成点）

### 2.1 PageInfo + PageHeader 添加 ChunkPos

```go
// btree/page_info.go — 修改
type PageInfo struct {
    // ... 现有字段不变 ...
    ChunkPos model.ChunkPosition // AO 位置 (0=脏页，对齐 Lealone pos==0 语义)
}

// offheap/page_layout.go — 修改
type PageHeader struct {
    // ... 现有字段不变 ...
    chunkPos uint64    // 辅助校验字段（非权威，PageInfo.ChunkPos 为权威）
    _        [8]byte   // 填充（从 [16]byte 减为 [8]byte）
}
```

**双层设计**：
| 位置 | 作用 | 并发保护 |
|------|------|----------|
| `PageInfo.ChunkPos` | 权威持久化状态 | `PageRef.CAS` 原子发布 |
| `PageHeader.chunkPos` | 反序列化后自检 | `clearPage` 清零初始化 |

`SizeofPageHeader` 保持 56 字节不变。

```go

type OffheapBTreeStorage struct {
    pm         *offheap.PageManager
    pa         *offheap.PageAccessor
    cm         service.ChunkManager    // Phase 4.3 新增
    serializer *chunk.PageSerializer   // Phase 4.3 新增
    pageLocs   sync.Map                // map[PageID]ChunkPosition
    closed     atomic.Bool
}

// 新增：惰性加载路径
func (s *OffheapBTreeStorage) loadPage(pageID model.PageID) (unsafe.Pointer, error) {
    // 1. 尝试从 PageManager 获取
    // 2. 未命中 → pageLocs.Load(pageID) → cm.ReadPage(pos) → Deserialize
}

// 修改：COW 分配时将 chunkPos 清零
func (s *OffheapBTreeStorage) copyPage(...) (...) {
    // 新页面 chunkPos = 0（标记为脏页）
}

// 新增：批量更新 pageLocs
func (s *OffheapBTreeStorage) UpdatePageLocs(mapping map[model.PageID]model.ChunkPosition)

// 新增：FreePage 时清理 pageLocs（防止 pageID 复用后惰性加载旧数据）
func (s *OffheapBTreeStorage) FreePage(pageID model.PageID) error {
    s.pageLocs.Delete(pageID) // 必须在 Free 前删除，防止 COW 复用 ID 后的陈旧引用
    return s.pm.FreePage(pageID)
}

// copyPage (COW) 时新页面 chunkPos 清零
func (s *OffheapBTreeStorage) copyPage(srcID model.PageID) (model.PageID, unsafe.Pointer, error) {
    newID, ptr, err := s.pm.CopyPage(srcID)
    if err != nil {
        return 0, nil, err
    }
    // 新分配的 COW 页面标记为脏页（chunkPos=0）
    s.pageLocs.Store(newID, uint64(0))
    return newID, ptr, nil
}
```

**pageLocs 生命周期关键规则**：

| 操作 | pageLocs 动作 | 原因 |
|------|-------------|------|
| COW (copyPage) | `Store(newID, 0)` | 新页面 = 脏页 |
| Checkpoint 成功 | `Store(pageID, pos)` | 标记为已持久化 |
| FreePage | `Delete(pageID)` | 防止 ID 复用后读取陈旧 AO 数据 |
| Restore | `Load(pageID)` → 惰性加载 | 从 CheckpointEntry 恢复 |

### 2.3 BTreeScanner 接口扩展

```go
// checkpoint/checkpoint_manager.go — 修改
type BTreeScanner interface {
    RootPage() PageRef
    EnumeratePages(root PageRef) ([]PageFlushItem, error)  // 新增
}

type PageFlushItem struct {
    PageID   model.PageID
    PageType uint8
    PageData []byte              // 预序列化数据（nil = 已持久化，跳过）
    ChunkPos model.ChunkPosition // 0 = 脏页
}
```

**实现位置**：`btree/` 包内（需访问 `PageRef.children`、`pInfo` 等未导出字段）。

**DFS 并发安全**：遍历期间对每个 PageRef 调用 `Retain()`/`Release()`，防止并发 Free+Alloc 导致的 TOCTOU。

### 2.4 CheckpointManager 集成

**关键决策**：统一类型体系 — 让 `wal` 包使用类型别名引用 `service` 类型（对齐 `mvcc/transaction.go` 的模式）。

**Step 0（预迁移）**：让 `DiskWAL` 实现 `service.WAL` 接口。

**障碍**：`wal/types.go` 在 `WALEntry`/`WALType` 上定义了方法（Go 不允许为别名类型定义方法）：
- `(e *WALEntry) Marshal() ([]byte, error)` — 8 处调用
- `(e *WALEntry) Unmarshal(data []byte) error`
- `(wt WALType) String() string`

**Step 0a**：将方法转为包级函数（消除方法冲突）：
```go
// Before: entry.Marshal()
// After:  MarshalWALEntry(entry)
func MarshalWALEntry(e *WALEntry) ([]byte, error) { ... }
func UnmarshalWALEntry(data []byte) (*WALEntry, error) { ... }
func WALTypeString(wt WALType) string { ... }
```

影响范围：8 个调用点改为函数调用（`entry.Marshal()` → `MarshalWALEntry(entry)`）。

**Step 0b**：添加类型别名（对齐 `mvcc/transaction.go` 模式）：
```go
// wal/types.go
type WALEntry = service.WALEntry
type LSN      = service.LSN
type WALType  = service.WALType
```

别名后 `DiskWAL` 自动满足 `service.WAL`，无需适配器。

**Step 0 验证**：`go build ./internal/infrastructure/storage/wal/...` + `go test ./internal/infrastructure/storage/wal/...` 全部通过。


**影响范围**：
- `checkpoint.WALWriter` → 删除（替换为 `service.WAL`）
- `checkpoint.LSN` / `checkpoint.WALEntry` → 删除（替换为 `service.LSN` / `service.WALEntry`）

### 2.5 Recovery 集成（RecoveryManager）

```go
// wal/recovery_manager.go — 新增 RecoveryManager（新文件，避免 recovery.go 过长）
type RecoveryManager struct {
    wal        service.WAL
    cm         service.ChunkManager
    serializer *chunk.PageSerializer
}

// Recover 三阶段恢复
func (rm *RecoveryManager) Recover(ctx context.Context) (*btree.BTree, error)
```

**三阶段恢复**（详见原始 spike §6.4.1）：
```
Phase A: 基础设施初始化
  1. ChunkManager 初始化（NewDiskChunkManager 或 RestoreDiskChunkManager）
  2. PageManager 初始化（空 mmap 池）
  3. WAL 扫描 → 找最新 CheckpointEntryV2

Phase B: BTree 结构重建（有 CheckpointEntryV2 时）
  4. 解析 CheckpointEntryV2 → rootPageID + pageLocs 映射
  5. OffheapBTreeStorage.pageLocs ← mapping
  6. RebuildBTree(rootPageID, pageLocs) → PageRef 图
     (所有页面在访问时惰性加载)

Phase C: 增量 WAL 重放
  7. 从 checkpointStartLSN 开始重放 WAL
  8. 重建 VersionChain
```

## 三、惰性加载路径

```
读取流程:
  GetLeafPage(pageID):
    1. page := pm.PageIDToPtr(pageID)
    2. if page.IsValid() → return page
    3. pos, ok := pageLocs.Load(pageID)
    4. if !ok → return ErrPageNotFound
    5. rawPageID := pm.Alloc()
    6. data := cm.ReadPage(pos)
    7. serializer.Deserialize(data, pm.PageIDToPtr(rawPageID))
    8. 校验 pageType（自检 chunkPos 字段）
    9. return page
```

**性能特征**：首次访问触发一次 `ReadAt` + `Deserialize`；后续访问走 mmap 缓存（零 I/O）。

## 五、风险与缓解

| 风险 | 缓解 |
|------|------|
| `wal.WALEntry` 方法（Marshal/Unmarshal/String）与类型别名冲突（C2） | Step 0a 方法→函数转换 + Step 0b 类型别名，8 个调用点更新，编译+测试验证 |
| `WALTypeCheckpointV2 = 6` 与 `WALTypeSplit` 冲突（C1） | 使用 `WALTypeCheckpointV2 = 7`，FormatVersion 前缀检测 |
| pageID 复用后 `pageLocs` 残留导致惰性加载旧数据（C3） | `FreePage` 中调用 `pageLocs.Delete(pageID)`，COW 时 `Store(newID, 0)` |
| checkpoint 类型统一影响范围大（H2） | Step 0 预迁移 + Step 1 独立编译验证，mockWAL 更新约 12 处 |
| FormatVersion 检测与 Phase 3 兼容（H3） | `Key[0] == 0x04`（Phase 4）vs `Key[0] == 0x03` 或无前缀（Phase 3），非长度检测 |
| EnumeratePages 的 Retain/Release TOCTOU | 严格遵循 Retain→DFS→Release 协议 |
| PageHeader 字段重排导致向后不兼容 | `chunkPos` 使用填充区（小端序），`SizeofPageHeader` 不变 |
