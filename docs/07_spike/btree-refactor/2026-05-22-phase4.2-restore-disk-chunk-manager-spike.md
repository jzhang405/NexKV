## 一、现有代码审计

`RestoreDiskChunkManager` 已实现 8 步恢复协议的骨架（`disk_chunk_manager.go:338-464`）：

| 步骤 | 描述 | 状态 |
|------|------|------|
| 1 | 扫描目录 `os.ReadDir` | ✅ |
| 2 | 删除零长度文件 | ✅ |
| 3 | 解析文件名 + 去重（同 chunkID 留最高 seq） | ✅ |
| 4 | 按 seq 排序 | ✅ |
| 5 | 双块 header 验证（block 0 / block 1 fallback） | ✅ |
| 6 | 重建内存结构（chunkIDs, idToChunk, seqToID, chunks） | ✅ |
| 7 | 恢复 pagePosToLen + removedPages | ❌ TODO(phase4.3) |
| 8 | 恢复 RootPagePos | ❌ TODO(phase4.3) |

**核心缺口**：header 解析通过后，`pagePosToLen` 和 `removedPages` 初始化为空 map（line 435-436）。实际页面元数据存储于 chunk body 中，需要通过 `PagePositionAndLengthOffset` 和 `RemovedPageOffset` 反序列化恢复。

**缺口根因**：这些元数据由 Phase 4.3 的 `FuzzyCheckpoint` 流程写入。Phase 4.2 时 chunk body 还没有页面数据，所以恢复只能读到 header。

## 二、当前设计约束

### 2.1 页面数据写入时机

当前 Checkpoint 流程（`checkpoint/checkpoint_manager.go`）只检查 `ChunkPos`：

```go
// checkpoint_manager.go:FuzzyCheckpoint
if page.ChunkPos == 0 {
    // 新页/脏页 → cm.Allocate + cm.WritePage
} else {
    // 已持久化 → 跳过
}
```

问题是：**pagePosToLen 和 removedPages 在 ChunkManager 内存中维护，但从未序列化到 .ao 文件**。Close 时 `writeHeader` 填充了这些字段，但它们的**实际数据**没有写入文件——只有 header 文本写入了。

### 2.2 ChunkHeader 的序列化范围

`ChunkHeader` 有 `PagePositionAndLengthOffset` 和 `RemovedPageOffset` 字段，但：
1. **写入时**：encode() 输出这些字段，但值是 0（`Close()` 在 `disk_chunk_manager.go:243-258` 填充了 SumOfLivePageLength 等，但**没有填充 offset 字段**）
2. **读取时**：decodeHeader() 解析这些字段，但 recovery 忽略了它们的值

## 三、最小实现方案

### 决策 1：Phase 4.2 做什么

**不等到 Phase 4.3**。Phase 4.2 完成 "header 恢复即可用" 的标准——即恢复后 `DiskChunkManager` 可以正常执行 `Allocate`、`WritePage`、`FreePage`、`ReadPage`。

具体含义：
- `pagePosToLen` 直接重建：通过扫描 chunk body 中的每个 PageFrame header 恢复
- `removedPages` 直接重建：通过检查 PageFrame header 中的 `deleted` 标记恢复
- 不依赖 `PagePositionAndLengthOffset` / `RemovedPageOffset`（这两个字段延后到 Phase 4.3 正式支持）

### 决策 2：PageFrame 扫描恢复

每个已写入 Chunk 的页面使用 `page_serializer.go:Serialize()` 产生的 PageFrame 格式：

```
PageFrame = header(7B) + compressedPageData(variable)
header = CRC32(4B) + originalLength(2B) + compressedFlag(1B)
```

Phase 4.2 在恢复时**逐页扫描** chunk body，对每个 PageFrame：
1. 验证 CRC32
2. 根据 originalLength 计算该页在 Chunk 中的 offset 和 length
3. 重建 `pagePosToLen[pos] = frameLength`

### 决策 3：removedPages 恢复

`page_serializer.go:PageFrameHeader.compressedFlag` 无法区分 "removed" vs "normal" 页面。

**两个选择**：
- **A**：在 Serialize 格式中新增 removed flag（1 bit from compressedFlag 保留位）→ 改动 `page_serializer.go`
- **B**：Phase 4.2 不恢复 removedPages（初始化为空），Phase 4.3 通过 header offset 恢复 → 无代码改动

**选择 B**。理由：removedPages 用于 ChunkCompactor 的 GC 决策。Phase 4.2 聚焦恢复可读写状态，GC 是 Phase 4.4 的职责。恢复后将 `removedPages` 初始化为空意味着所有页面被视为 "live"，这是保守安全的——over-count 不会导致数据丢失（最多导致 GC 延迟）。

## 四、实现计划

### Step 1: 恢复 pagePosToLen by PageFrame scan

```go
// chunk_file.go 新增

// scanPageFrames walks the chunk body and rebuilds pagePosToLen.
func (c *ChunkFile) scanPageFrames() (map[model.ChunkPosition]int32, error) {
    result := make(map[model.ChunkPosition]int32)
    offset := int64(ChunkHeaderSize)
    
    hdrBuf := make([]byte, PageFrameHeaderSize) // 7 bytes
    for offset < c.capacity {
        // Try to read frame header
        n, err := c.file.ReadAt(hdrBuf, offset)
        if err != nil || n < PageFrameHeaderSize {
            break // end of written data
        }
        
        hdr, err := parsePageFrameHeader(hdrBuf)
        if err != nil {
            break // corrupted frame → stop
        }
        
        frameLen := int32(PageFrameHeaderSize + hdr.originalLength)
        pos, _ := model.EncodeChunkPosition(c.id, uint32(offset), 0 /* pageType unknown at frame level */)
        result[pos] = frameLen
        offset += int64(frameLen)
    }
    return result, nil
}
```

> **约束**：`model.EncodeChunkPosition` 需要 `pageType`，但 PageFrame header 不含 pageType。恢复时传入 0 会导致 pageType 信息丢失。**Phase 4.2 接受这个限制**——pageType 仅用于 ChunkManager.Allocate 的校验，不影响 ReadPage/FreePage 的 ChunkID+Offset 定位。

### Step 2: 集成到 RestoreDiskChunkManager

```go
// Step 7 修改: 从 header 恢复 → 从 PageFrame scan 恢复
c := &ChunkFile{
    id:           fe.chunkID,
    seq:          fe.seq,
    file:         f,
    capacity:     st.Size(),
    nextOffset:   ChunkHeaderSize,
    pagePosToLen: make(map[model.ChunkPosition]int32),
    removedPages: make(map[model.ChunkPosition]struct{}),
}

// 验证 header
if _, err := c.readHeader(); err != nil {
    f.Close()
    continue
}

// ★ Phase 4.2: 从 chunk body 扫描恢复 pagePosToLen
pageLens, scanErr := c.scanPageFrames()
if scanErr != nil {
    // 扫描失败不阻塞恢复——pagePosToLen 为空时 ReadPage 会返回 ErrPageNotFound
    // 上层惰性加载路径可通过 ReadPage 重试
}
c.pagePosToLen = pageLens
c.nextOffset = int64(ChunkHeaderSize)
for pos, l := range pageLens {
    if int64(pos.FileOffset())+int64(l) > c.nextOffset {
        c.nextOffset = int64(pos.FileOffset()) + int64(l)
    }
}
```
