结合 NexKV 分布式 KV 系统的核心设计（libp2p RPC、分片集群、Fanout 模式、性能优化等），除了你列出的 **Host 元数据、分片元数据、节点元数据、表元数据、分布式锁** 外，还有以下**核心元数据/关键配套组件**（按“元数据类”和“核心组件类”分类，均贴合分布式 KV 生产级落地需求）：

## 一、核心元数据类（补充分布式 KV 必备的元数据维度）
### 1. 路由元数据（分片/Key 路由）
- **核心作用**：映射「Key/表」到「分片/节点/副本」的核心路由规则，是分布式 KV 寻址的基础。
  - 包含：一致性哈希环映射、Key 范围→分片 ID 映射、分片→副本节点列表、路由版本（防止路由漂移）。
- **适配 NexKV 场景**：
  - Fanout 模式下，根据路由元数据筛选「目标分片的有效 peer 列表」，避免向非目标节点发送请求；
  - 连接池根据路由元数据预热「高频访问节点的 Stream 连接」，提升 Stream 复用率。

### 2. 版本元数据（数据/集群版本）
- **核心作用**：解决分布式一致性问题，防止脏写/脏读、适配配置变更。
  - 包含：数据版本（MVCC 版本号）、集群配置版本（拓扑/分片变更版本）、元数据更新时间戳、乐观锁版本。
- **适配 NexKV 场景**：
  - Quorum 模式下，版本元数据用于验证「副本数据一致性」（如所有成功节点的版本号需一致）；
  - 分片元数据更新时，通过版本号避免并发修改冲突（如旧配置覆盖新配置）。

### 3. 健康状态元数据（节点/分片健康度）
- **核心作用**：记录节点/分片的存活、负载、故障状态，是容错/负载均衡的基础。
  - 包含：节点心跳时间、分片负载（QPS/内存/磁盘）、故障标记（宕机/网络异常/限流中）、恢复倒计时。
- **适配 NexKV 场景**：
  - Fanout 模式自动过滤「故障节点」，避免向不可用 peer 发送请求，降低 Fanout 延迟；
  - 连接池根据节点健康状态动态调整「最大 Stream 数」，避免过载节点占用资源。

### 4. 拓扑元数据（集群拓扑结构）
- **核心作用**：描述集群的层级/网状关系，适配树形协调器、跨层级 Fanout 转发。
  - 包含：节点父/子关系、分片所属拓扑层级、跨机房/可用区映射、网关节点列表。
- **适配 NexKV 场景**：
  - Hops 跳数转发时，根据拓扑元数据选择「下一跳节点」，避免循环转发；
  - Quorum 节点优先从「同层级/同可用区」选择，降低网络延迟。

### 5. 性能元数据（监控/统计）
- **核心作用**：记录节点/分片/表的性能指标，支撑性能优化和监控告警。
  - 包含：节点 QPS/P99 延迟、Stream 复用率、Fanout 成功率、批量调用耗时、限流触发次数。
- **适配 NexKV 场景**：
  - 自动识别「性能瓶颈节点」，调整 Fanout 并发数/超时时间；
  - 连接池根据 Stream 复用率动态调整 TTL，平衡性能和资源占用。

### 6. 权限元数据（访问控制）
- **核心作用**：生产级必备，管控节点/用户对表/分片的读写权限。
  - 包含：节点访问白名单、表级读写权限、分片操作权限、Token/证书有效期。
- **适配 NexKV 场景**：
  - RPC 层接入权限元数据，防止非法节点调用 Fanout 接口；
  - 分布式锁仅允许「有权限的节点」抢占，避免权限越界。

### 7. 快照/备份元数据
- **核心作用**：管理数据快照/备份的生命周期，适配灾备和数据恢复。
  - 包含：快照时间、分片覆盖范围、存储路径、备份版本、恢复优先级。
- **适配 NexKV 场景**：
  - 分片元数据损坏时，通过快照元数据快速恢复；
  - Fanout 模式支持「快照同步」RPC，元数据记录同步进度。

### 8. 事务元数据（分布式事务）
- **核心作用**：若 NexKV 支持分布式事务，需记录事务上下文。
  - 包含：事务 ID、参与者节点列表、事务状态（准备/提交/回滚）、超时时间。
- **适配 NexKV 场景**：
  - Quorum 模式下，事务元数据用于「多节点事务一致性确认」；
  - 分布式锁与事务元数据绑定，防止事务未完成时锁被释放。

## 二、关键配套组件（非纯元数据，但属于分布式 KV 核心能力）
### 1. 心跳/续租组件（元数据配套）
- **核心作用**：维护节点存活状态、分布式锁续租、元数据实时同步。
  - 包含：心跳间隔、锁续租周期、元数据同步 Ack、失联阈值。
- **适配 NexKV 场景**：
  - 分布式锁通过续租元数据避免「锁超时释放」；
  - 节点心跳异常时，自动从 Fanout 节点列表中剔除。

### 2. 限流/熔断元数据（规则+状态）
- **核心作用**：管控流量，防止集群过载，适配之前提到的 RateLimiter 模块。
  - 包含：节点/表级 QPS 阈值、熔断触发阈值（错误率/延迟）、熔断恢复时间、限流白名单。
- **适配 NexKV 场景**：
  - RPC 层根据限流元数据动态调整 RateLimiter 参数；
  - Fanout 模式对「熔断节点」直接返回降级结果，不发送请求。

### 3. 日志元数据（操作/审计日志）
- **核心作用**：审计操作、回溯故障，生产级合规必备。
  - 包含：操作人/节点 ID、操作类型（元数据修改/Fanout 调用）、操作时间、结果、关联 Key/分片。
- **适配 NexKV 场景**：
  - Fanout 调用异常时，通过日志元数据定位「哪个 peer 响应异常」；
  - 分布式锁抢占/释放操作记录，便于故障溯源。

### 4. 配置元数据（全局/局部配置）
- **核心作用**：统一管理集群配置，避免分散配置导致的不一致。
  - 包含：Quorum 阈值、Stream 缓存 TTL、Fanout 超时/并发数、连接池最大连接数。
- **适配 NexKV 场景**：
  - FanoutOptions 的默认值（如 Quorum 阈值）从配置元数据读取，无需用户手动传参；
  - 配置变更时，通过版本元数据同步到所有节点，避免配置漂移。

### 5. 迁移元数据（分片/数据迁移）
- **核心作用**：管理集群扩缩容时的分片迁移流程。
  - 包含：迁移任务 ID、源/目标节点、分片范围、迁移进度、暂停/恢复标记。
- **适配 NexKV 场景**：
  - 迁移过程中，Fanout 模式自动向「源+目标节点」发送请求，保证数据一致性；
  - 连接池预热目标节点的 Stream 连接，降低迁移后的访问延迟。

### 6. 索引元数据（二级索引）
- **核心作用**：若 NexKV 支持结构化查询，需维护二级索引映射。
  - 包含：索引名称、索引字段、索引→Key 映射、索引版本。
- **适配 NexKV 场景**：
  - 表元数据关联索引元数据，Fanout 模式支持「索引查询广播」。

## 总结
### 关键点回顾
1. **核心补充元数据**：路由、版本、健康状态、拓扑元数据是 NexKV 分布式 KV 的“基础骨架”，直接适配 Fanout 模式、Quorum 机制、连接池的核心逻辑；
2. **配套组件**：心跳/续租、限流/熔断、配置元数据是生产级落地的“必备保障”，解决容错、限流、配置一致性问题；
3. **场景关联**：所有补充项均贴合之前提到的 RPC 性能优化（5000+ calls/sec）、Fanout 延迟目标（P99<50ms）、Stream 复用率>90% 等核心目标；
4. **设计原则**：新增元数据需与现有体系（如集群层 Quorum、统一错误码）对齐，避免重复定义，降低维护成本。

这些元数据/组件覆盖了分布式 KV 从“寻址→一致性→容错→性能→安全→运维”的全链路需求，是 NexKV 从“基础框架”到“生产级系统”的关键补充。
