## 测试场景规划

### 场景 1：Leader 宕机

**测试步骤**：
```bash
# 1. 启动 3 节点集群
make start-cluster NODES=3

# 2. 找到 leader PID
pgrep -f "node.*leader" | head -1

# 3. 杀掉 leader
kill -9 <PID>

# 4. 观察日志，看新 leader 是否选出
tail -f logs/node-*.log | grep "leader"
```

**预期行为**：
- [ ] 其他节点检测到 leader 宕机
- [ ] 触发新一轮 leader 选举
- [ ] 新 leader 被选出
- [ ] 集群继续提供服务

**关键日志**：
```
[INFO] Node leader-1 failed, starting election
[INFO] Node node-3 became new leader with term 5
```

---

### 场景 2：网络分区

**测试步骤**：
```bash
# 1. 使用 iptables 隔离节点
sudo iptables -A INPUT -s <node_ip> -j DROP
sudo iptables -A OUTPUT -d <node_ip> -j DROP

# 2. 观察集群行为
# 预期：多数派侧继续工作，少数派停止写入

# 3. 恢复网络
sudo iptables -D INPUT -s <node_ip> -j DROP
sudo iptables -D OUTPUT -d <node_ip> -j DROP
```

**预期行为**：
- [ ] 多数派（≥3 节点）继续接受写入
- [ ] 少数派（<3 节点）拒绝写入或降级为只读
- [ ] 网络恢复后自动重新同步

---

### 场景 3：节点恢复测试

**测试步骤**：
```bash
# 1. 在场景 1 的基础上，重启被杀掉的节点
make start-node NODE_ID=node-1

# 2. 验证节点成功加入集群
# 3. 检查数据是否自动同步
```

**预期行为**：
- [ ] 节点成功连接到种子节点
- [ ] 节点获取最新的元数据
- [ ] 没有数据丢失或损坏

---

### 场景 4：边界条件测试

#### 4.1 最小集群（2 节点）

**测试步骤**：
```bash
make start-cluster NODES=2
```

**预期行为**：
- [ ] 集群正常工作
- [ ] Quorum = 2（需要全部节点同意）

#### 4.2 快速启停节点

**测试步骤**：
```bash
for i in {1..10}; do
  make start-node NODE_ID=test-$i
  sleep 0.5
  make stop-node NODE_ID=test-$i
done
```

**预期行为**：
- [ ] 无 panic 或崩溃
- [ ] 无资源泄漏
- [ ] 节点正确清理

#### 4.3 资源限制

**测试步骤**：
```bash
# 限制内存可用（模拟资源受限场景）
ulimit -v 1024

# 启动节点
make start-node NODE_ID=node-1
```

**预期行为**：
- [ ] 优雅降级而非崩溃
- [ ] 记录适当的错误日志
