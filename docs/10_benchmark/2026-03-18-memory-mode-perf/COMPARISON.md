# NexKV vs Lealone 纯内存模式性能对比报告

**日期**: 2026-03-18
**测试配置**:
- 数据集大小: 1M 记录
- 测试模式: 纯内存 (in-memory, /dev/shm)
- GC 设置: GOGC=400 (NexKV), G1GC (Lealone)
- 每线程操作数: 10,000 次 Set 操作

---

## 🔍 关键发现

### 1. 单线程性能几乎相同

```
NexKV:  515,539 ops/sec (1.94 μs/op)
Lealone: 514,928 ops/sec (1.94 μs/op)
差距:    0.1%
```

**结论**: 纯内存单线程场景下，两者性能基本一致。

### 2. 多线程扩展性差距巨大

| 线程数 | NexKV 扩展比 | Lealone 扩展比 | 差距 |
|--------|-------------|---------------|------|
| 1 → 2 | 0.95x ↓ | 1.27x ↑ | Lealone 优 |
| 1 → 4 | 1.03x ~ | 2.56x ↑ | Lealone 优 |
| 1 → 8 | 1.06x ~ | 4.03x ↑ | **Lealone 显著优** |

**根因分析**:
- **NexKV**: 根 CAS 机制导致高并发时竞争加剧
- **Lealone**: 叶子级别锁定 + 异步分裂，并发扩展性优秀

### 3. 8 线程性能差距接近 4 倍

```
NexKV 8 线程: 548,059 ops/sec
Lealone 8 线程: 2,073,742 ops/sec
差距: 3.78x (278%)
```

**结论**: 高并发场景下，Lealone 的叶子级别锁定优势明显。

## 🎯 优化建议

基于实际测试数据，NexKV 的合理优化目标：

| 指标 | 当前值 | 短期目标 | 长期目标 |
|------|--------|----------|----------|
| 2 线程 | 492K | 600K (22%) | 650K (32%) |
| 4 线程 | 529K | 700K (32%) | 1,000K (89%) |
| 8 线程 | 548K | 800K (46%) | 1,500K (174%) |

**优化方向优先级**:
1. **P0**: 引入叶子级别锁定 (预期 8 线程 2x 提升)
2. **P1**: 实现异步分裂 (减少 CAS 持有时间)
3. **P2**: 优化路径复制开销

## 📝 测试环境说明

### NexKV 测试环境

```
硬件: Linux x86_64
Go版本: 1.24+
GC: GOGC=400
数据集: 1M keys
存储: 纯内存模式
工具: cmd/btree_perf_mem/main.go
```

### Lealone 测试环境

```
语言: Java
JVM参数: -Xms2g -Xmx2g -XX:+UseG1GC

工具: SimplePerfTest.java
```

### 环境差异

- **GC**: NexKV 使用 Go GC，Lealone 使用 G1GC
- **内存管理**: Go 的内存管理 vs Java 的堆管理
- **实现语言**: Go vs Java

---

## 结论

1. **单线程**: 两者性能相当，差距可忽略
2. **多线程**: Lealone 显著优于 NexKV（最高 3.78x）
3. **扩展性**: Lealone 实现了近乎线性的扩展，NexKV 存在扩展性问题
4. **优化价值**: 叶子级别锁定优化对 NexKV 至关重要

**关键启示**: Lealone 的叶子级别锁定机制是其高并发性能的核心，这验证了优化方向的正确性。
