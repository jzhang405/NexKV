## 3. 扩展性分析

| 线程数 | 成功率 | 吞吐量 (ops/s) | 扩展比 | 延迟 (μs/op) |
|--------|--------|---------------|--------|-------------|
| 1 | 14.06% | 55,809 | 1.00x | 18 |
| 2 | 6.43% | 6,866 | **0.12x** | 146 |
| 4 | 3.51% | 6,704 | **0.12x** | 149 |
| 8 | 2.09% | 8,270 | **0.15x** | 121 |

**关键发现**：

1. **负扩展**：从 1 线程到 2 线程，吞吐量下降 8x（55K → 7K）。这不是线性下降，是**崩溃式下降**。
2. **成功率断崖**：1 线程 14% → 2 线程 6% → 4 线程 3.5% → 8 线程 2%。每翻倍线程，成功率约减半。
3. **2-8 线程几乎持平**：吞吐量在 6-9K ops/s 之间波动，增加线程无法提升性能。
4. **延迟暴增**：1 线程 18μs → 2 线程 146μs（8x），此后稳定在 100-150μs。

## 5. 根因摘要

```
8 线程竞争同一热点叶子锁：
  TryLock CAS 失败 → 立即 ErrRetry → runtime.Gosched()
    → schedule (30%) + park_m (28%) + futex (14%)
      → 调度风暴，CPU 80%+ 浪费
        → TaskScheduler 单线程兜底 → 串行化
```

**优化目标**（Phase-PageLock）：
- 成功率：2% → 30-50%
- 吞吐量：8K ops/s → 50-100K ops/s
- CPU 有效利用率：19% → 60%+
